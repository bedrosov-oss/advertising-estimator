# Интернет-версия 1.0.10: размещение и обновления

Исходники готовы к размещению. Публикация в GitHub и запуск действующего сайта должны быть подтверждены отдельными успешными результатами: наличие файлов не означает, что сайт уже работает.

## Как устроена версия

GitHub хранит код и историю версий. Render запускает Python-сервис постоянно, выдаёт HTTPS-адрес и подключает диск `/var/data/estimator`. SQLite-базы, документы и проекты находятся на этом диске и переживают обновления кода. GitHub Pages предназначен для статических страниц и не запускает эту серверную часть.

Вход — по паролю владельца одного рабочего пространства. Это не многопользовательская система с раздельными организациями и ролями. Пароль от 16 символов задаётся в `ESTIMATOR_OWNER_PASSWORD`, не в репозитории и не в чате. Сеанс действует 8 часов; после перезапуска сервиса нужно войти снова. Проекты при этом сохраняются. Выход из аккаунта не останавливает сервер или расписание.

## Что настроить для первого размещения

1. Создайте отдельный репозиторий `advertising-estimator` в своём GitHub. Подходит закрытый репозиторий. Не помещайте программу в репозитории других задач. Дайте подключению ChatGPT доступ именно к нему.
2. Загрузите исходники выпуска в корень репозитория, сохраняя структуру папок. Для Git-истории можно клонировать приложенный `.bundle`, добавить свой GitHub как `origin` и выполнить обычный push без force. Пароли, API-ключи и папки рабочих данных в Git не загружайте.
3. В Render создайте Blueprint из репозитория; файл настройки — `render.yaml`. Он описывает постоянно работающий Python-сервис, диск 1 ГБ и публикацию после успешных проверок. Выбран `1c-2g` для запаса памяти на PDF/Excel/чертежи. Render-сервис и постоянный диск платные; согласуйте отображаемый Render тариф до запуска. Оплата не выполнялась при подготовке исходников.
4. Задайте `ESTIMATOR_OWNER_PASSWORD`. При необходимости доставки задайте `APISHIP_TOKEN`; для работы смет он не нужен, значение можно оставить пустым. Для собственного домена дополнительно задайте `PUBLIC_ORIGIN=https://ваш-домен`; иначе используется `RENDER_EXTERNAL_URL`.
5. Дождитесь состояния Live и успешного `/healthz`. Откройте выданную ссылку, войдите, создайте учебный проект, сохраните и проверьте его после повторного входа и тестового обновления сервиса.
6. В «Автоподборе и доставке» подключите подготовленные прайсы. Ежедневная задача выполняется в самом сервере, её работа не зависит от открытого чата или браузера.

На один постоянный диск рассчитан один экземпляр сервиса. Не запускайте несколько серверных процессов с независимыми планировщиками на этой же базе. Обновление сервиса с диском может кратковременно прервать доступ. Для больших документов/баз увеличивайте ресурсы после наблюдения фактической нагрузки.

## Перенос ранее сделанных проектов

Файлы с вашего компьютера не могут появиться на сервере без переноса.

- Для отдельных заказов: в настольной версии скачайте JSON; на сайте выберите «Файл → Открыть файл · JSON», затем «Сохранить смету».
- Для всех записей базы: в настольной версии скачайте JSON-копию базы, на сайте в «Моих заказах» откройте её через восстановление. Импорт добавляет записи отдельными копиями, не стирая существующие. При уже заведённых складских остатках импорт JSON ограничен для сохранения связей.
- Для переноса склада, журналов, настроек ежедневной проверки и исходных документов нужен полный ZIP. Его распаковывают в новую пустую постоянную папку **до запуска сервера**, сохранив прежнюю копию отдельно. Обычный JSON этого набора не содержит. В ZIP версии 1.0.9 входит также `supply-hub.sqlite`.

Перед обновлением сохраняйте полную резервную копию из «Моих заказов». Проекты и рабочая база не включаются в репозиторий; смена версии сайта не должна пересоздавать диск. Пароли и ключи переносятся через настройки хостинга отдельно.

## Ежедневные цены и наличие

Раздел «Обновление цен» по-прежнему принимает старые CSV/XLSX/PDF и карточки товаров для проверки вручную. Новый «Автоподбор и доставка» принимает JSON/CSV по строгой схеме [SUPPLIER_FEEDS.md](SUPPLIER_FEEDS.md): нужен не только ценник, но и подтверждённое наличие и остаток. Названия сами по себе не определяют взаимозаменяемость; ключ материала задайте одинаково только для согласованных аналогов.

Каждые 24 часа обновляется база предложений. Сохранённые сметы не пересчитываются задним числом. При ошибке старые сведения остаются видимыми в диагностике, но исключаются из автоматического выбора. Пропущенная проверка после запуска выполняется один раз; результаты старше суток не участвуют в подборе.

Текущая реализация выбирает минимальную стоимость материала с учётом упаковки и минимального отпуска. Доставка считается отдельно для конкретного груза. Это не оптимизация общей закупки у нескольких поставщиков и не оформление заказа.

## Ежедневная доставка

Сохраните точные адреса, общий вес в граммах, габариты в сантиметрах, оценочную стоимость, тип забора и коды перевозчиков ApiShip. На сервере нужен `APISHIP_TOKEN`, в ApiShip — подходящие подключения к перевозчикам.

Версия рассчитывает доставку до двери в России, без наложенного платежа. Выбирает минимальный из возвращённых тарифов для заданного способа забора. Неопределённые сборы исключаются; сборы учитываются, когда API сообщает их отдельно. Итог — оценка для указанного груза, а не заказ перевозки. При изменении груза создайте новый маршрут или пересоздайте его настройки. Русский OCR и перевозчики должны быть проверены с реальными данными после размещения.

## Как обновлять сайт из этого чата

После запроса на изменение обновляются код, номер версии и инструкция; проверки должны пройти. Затем изменения отправляются в подключённую ветку GitHub. `.github/workflows/web-checks.yml` запускает проверки; `render.yaml` использует `autoDeployTrigger: checksPass`. Render публикует прошедший проверку коммит автоматически. Для будущих обращений сохраняйте ссылку репозитория и сайта в материалах проекта.

Само сообщение в чате не меняет GitHub: исполнитель должен применить изменения и отправить коммит. Чтения всех сообщений чата из Render нет. Отдельная фоновая задача ChatGPT для обновления цен не создаётся: расписание является частью программы.

## Проверка реализации

Тесты проверяют запрет неавторизованного доступа, сеанс/CSRF/выход, сохранение записей при смене экземпляра входного сервиса, расчёт упаковок и остатков, исключение устаревших предложений, ежедневное расписание, разбор стоимости доставки и включение новой базы в резервную копию. Действующий HTTPS-сайт и реальный тариф перевозчика подтверждаются только после успешного размещения и настройки доступов.

Официальные сведения: [Render: постоянные диски](https://render.com/docs/disks), [Render: настройки и автоматическое размещение](https://render.com/docs/blueprint-spec), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [ApiShip: калькулятор](https://docs.apiship.ru/docs/api/calculator/), [Waitress](https://docs.pylonsproject.org/projects/waitress/en/stable/).

## Репозиторий для публикации

Используется https://github.com/bedrosov-oss/advertising-estimator, ветка main. После загрузки кода откройте https://dashboard.render.com/blueprint/new?repo=https://github.com/bedrosov-oss/advertising-estimator. Выберите своё рабочее пространство, проверьте стоимость сервиса 1c-2g и диска 1 ГБ, задайте ESTIMATOR_OWNER_PASSWORD (от 16 символов). APISHIP_TOKEN можно оставить пустым до подключения доставки. Нажатие Apply запускает платный сервис; до подтверждения сайт не создан.

В 1.0.10 исправлен идентификатор тарифа по актуальной спецификации Render. Обновления сайта начнут работать после подключения Blueprint: изменения программы нужно загрузить в main, дождаться успешных GitHub Actions и публикации Render. Сообщение в чате само по себе не изменяет сайт.
