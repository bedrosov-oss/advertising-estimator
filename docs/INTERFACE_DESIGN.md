# Интерфейс сметчика 1.0.7: выбор и основания

Исследование: 14 сентября 2026 года. Цель — уменьшить поиск действий и риск перепутать сохранение, документы, прайсы и склад. Один объективно «самый оптимальный» интерфейс нельзя выбрать без наблюдения за работой конкретного сметчика; выбран подход, соответствующий задачам этой программы, с последующей проверкой основных сценариев.

## Использованные ориентиры

| Источник | Что изучено | Решение для сметчика |
|---|---|---|
| [Printavo](https://www.printavo.com/) | Связный процесс от расчёта предложения к дальнейшей работе с заказом | Четыре понятных перехода: заказ, позиции, проверка, документы |
| [Ordant для рекламного производства](https://ordant.com/why-sign-shop-management-software-must-be-simple-but-versatile/) | Простота представления рабочих данных и доступность основных сведений | Группы задач вместо плоского списка добавленных модулей; итог рядом с расчётом |
| [IBM Carbon: таблицы](https://carbondesignsystem.com/components/data-table/usage/) | Размещение действий, компактные заголовки, место для данных, раскрытие подробностей | Основное добавление позиции рядом с таблицей; редкие действия раскрываются отдельно |
| [Nielsen Norman Group: распознавание вместо запоминания](https://www.nngroup.com/articles/recognition-and-recall/) | Видимые подсказки и узнаваемые действия уменьшают необходимость помнить путь | Текстовые подписи, поиск разделов, контекстная инструкция с прямыми переходами |
| [Nielsen Norman Group: постепенное раскрытие](https://www.nngroup.com/articles/progressive-disclosure/) | Редкие настройки можно показывать по запросу | Реквизиты, примечания, импорт и шаблон Word раскрываются отдельно |

Это проектные выводы для данной программы, а не копирование чужого интерфейса и не доказательство превосходства над всеми программами рынка. Код, графика и фирменное оформление указанных продуктов не переносились.

## Что изменено

- Меню сгруппировано: сметы, материалы, производство, дополнительные возможности. Есть поиск и выделение текущего раздела.
- Основная кнопка «Сохранить смету» сохраняет заказ на компьютере. Операции JSON находятся в меню «Файл» и подписаны явно.
- Документы разделены на предложение заказчику и внутреннюю калькуляцию. Склад, подключения и резервная копия вынесены в соответствующие разделы.
- Над сметой — переходы по рабочим шагам. Учебный пример отмечен отдельно; состояние сохранения и замечания видны рядом с работой.
- Таблица допускает прямой ввод. Реквизиты и редкие поля раскрываются по запросу.
- Использованы единые цвета, отступы, типографика и подписи действий; ресурсы не требуют внешних шрифтов или CDN.
- Для узкого окна предусмотрено выдвижное меню; горизонтальная прокрутка ограничена таблицами. Добавлены видимый фокус, переход к содержимому, Escape, Ctrl/⌘+S и F1.

## Инструкция при следующих обновлениях

Исходный текст — `web/guide.json`. Он содержит 22 темы, действия перехода, дату, номер версии и отметку содержательной сверки. `guide.js` показывает текст в программе и создаёт скачиваемый HTML. `scripts/review_guide.py` после редакторской проверки создаёт такую же инструкцию `docs/USER_GUIDE.md`.

Проверка `scripts/check_release.py` входит в оба сценария упаковки и GitHub Actions. Она блокирует выпуск при несовпадении версии, изменении контролируемых исходников или текста после сверки, отсутствии обязательных тем и расхождении отдельного руководства. Проверка не может оценить смысл текста за разработчика: порядок содержательного обновления закреплён в AGENTS.md.

## Пределы проверки

Основные сценарии выполняются через jsdom с настоящим локальным сервером и тестовыми данными. Визуальные документы строятся из отрисованного DOM отдельно. Облачный браузер не разрешил открыть локальный адрес и HTML-файл; эти ограничения не обходились. Нативная отрисовка интерфейса в Safari, WebView2 и окне macOS здесь не проверена. Для оценки удобства в производстве нужна пробная рабочая смета на устройстве пользователя.
