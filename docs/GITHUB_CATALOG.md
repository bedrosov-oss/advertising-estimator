# GitHub: компоненты для сметчика рекламы и полиграфии

Подборка от 14.09.2026 для программы Advertising Estimator Mac 1.0.1 и дальнейшего развития Windows-версии.

Рассмотрено 35 профильных и технических репозиториев: 31 компонент или заготовка включены в основной каталог, ещё 4 приведены с причинами, по которым их не стоит брать за основу текущего выпуска. Это подборка по требованиям этого чата, а не полный перечень всех проектов GitHub.

Проверены доступные README и метаданные репозиториев; дополнительно открыты выборочные лицензии, выпуски и исходники парсеров ЗЕНОН/ФорДА. Сторонние программы не устанавливались, их тесты не запускались, действующие цены и ответы ФНС ими не получались. Оценки приоритета и применимости ниже — вывод для нашей архитектуры.

## Что уже есть в программе

Локальное Python-приложение с интерфейсом HTML/JavaScript, SQLite, ручным вводом, заказами и версиями, расчётами с Decimal, импортом CSV/XLSX, предпросмотром обновления цен, PDF/Excel, адаптерами DaData/ФНС и необязательными Tavily/Ollama. В выпуске 1.0.1 нет универсального PDF-импорта, смешанного/фигурного раскроя и проверенной нативной сборки на реальном Mac.

Задача развития — добавить адаптеры к существующим функциям. Расчёт денег, различение неизвестной и нулевой цены, проверка единиц и неизменность сохранённых смет должны сохраняться.

## Наиболее точное совпадение: парсеры поставщиков рекламных материалов

[Vink-Masterskaya/vink-master](https://github.com/Vink-Masterskaya/vink-master) содержит модули для ЗЕНОН, ФорДА, Remex, Fabreex, Tdppl и Oracal. В README указаны Python 3.10–3.12, Scrapy и Playwright. Прочитаны README, зависимости, модель записи, валидация и исходники двух основных парсеров.

Это полезная отправная точка для исследования структуры сайтов, но напрямую включать её в сметчик пока не следует:

- В [zenon.py](https://github.com/Vink-Masterskaya/vink-master/blob/main/competitors_parser/spiders/zenon.py) цена «по запросу», отсутствие цены и часть ошибок преобразуются в 0.0. Для сметчика это должно оставаться неизвестным значением и блокировать автоматическое применение.
- В [forda.py](https://github.com/Vink-Masterskaya/vink-master/blob/main/competitors_parser/spiders/forda.py) берётся первое значение из списка prices, а единица «шт» и валюта RUB задаются непосредственно в коде. Потребуются выбор предложения, проверка единицы, фасовки, налогового состава и региона.
- В [validation.py](https://github.com/Vink-Masterskaya/vink-master/blob/main/competitors_parser/pipelines/validation.py) есть дополнительные подстановки нулей и единицы «шт». Такая нормализация не подходит для подтверждения закупочной цены.
- Последний push по метаданным GitHub — 06.04.2025. Доступность текущих сайтов и совместимость с Python нашей программы этим не подтверждаются.
- Лицензия не указана в метаданных; отдельный файл лицензии в просмотренном дереве не найден. Перед заимствованием исходников нужно уточнить условия использования.

В коде ФорДА найден путь запроса /get_offers?id=…; это наблюдение по стороннему исходнику, а не подтверждение действующего официального API поставщика.

## Версии, лицензии и ограничения, которые влияют на выбор

- **APScheduler:** GitHub latest указывает стабильный выпуск [3.11.3](https://github.com/agronholm/apscheduler/releases/tag/3.11.3) от 28.06.2026. [README основной ветки](https://github.com/agronholm/apscheduler/blob/master/README.rst) предупреждает, что 4.0 — предварительная серия. Для внедрения ориентироваться на документацию выбранной стабильной версии.
- **Camelot:** [2.0.0](https://github.com/camelot-dev/camelot/releases/tag/v2.0.0) от 04.06.2026 требует Python 3.10+ и описывает дополнительные нейросетевые/OCR-компоненты. Старое общее утверждение «Camelot работает только с текстовыми PDF» не отражает весь набор возможностей этого выпуска.
- **pywebview:** проверена карточка выпуска [6.2.1](https://github.com/r0x0r/pywebview/releases/tag/6.2.1) от 15.04.2026. Совместимость нашего локального сервера с упаковкой нужно подтвердить отдельной сборкой.
- **PyInstaller:** проверен выпуск [6.22.3](https://github.com/pyinstaller/pyinstaller/releases/tag/v6.22.3) от 12.09.2026. В нашей программе был зафиксирован 6.22.2; новое число само по себе не является причиной менять рабочие зависимости без проверки. Лицензия описана в [COPYING.txt](https://github.com/pyinstaller/pyinstaller/blob/develop/COPYING.txt): GPL-2.0-or-later с Bootloader Exception и отдельными условиями для некоторых файлов.
- **Deepnest:** основной LICENSE — MIT, но [LICENSES.md](https://github.com/deepnest-next/deepnest/blob/main/LICENSES.md) перечисляет также GPLv3 и Boost. Нельзя считать все части репозитория исключительно MIT.
- **uv:** в README указан выбор Apache-2.0 или MIT; открыт [LICENSE-MIT](https://github.com/astral-sh/uv/blob/main/LICENSE-MIT). GitHub может показывать только одну лицензию.
- **keyring:** лицензия MIT указана в [pyproject.toml](https://github.com/jaraco/keyring/blob/main/pyproject.toml), хотя отдельный LICENSE в корне не найден.
- **Docling:** код MIT; лицензии моделей и сторонних компонентов отдельно. Проверен выпуск [2.127.0](https://github.com/docling-project/docling/releases/tag/v2.127.0) от 14.09.2026, но интеграция с нашим приложением не выполнялась.
- **Tavily:** [README](https://github.com/tavily-ai/tavily-python/blob/master/README.md) описывает режим search/extract без ключа с ограничениями. Это сведения основной ветки; подходящий опубликованный пакет, фактические лимиты и доступность ещё нужно проверить перед внедрением. Для полного набора возможностей требуется ключ.

Первый небольшой выпуск логично ограничить PDF-прайсом и одним проверенным поставщиком. Следующий номер при изменении программы — 1.0.2; данный документ содержит исследование, программа 1.0.1 в этом поручении не изменялась.

## Что требуется от реальных данных предприятия

Для проверки подключений нужны публичная ссылка или предоставленный файл прайса, нужный филиал/регион, примеры артикулов, единица продажи, фасовка, валюта, состав цены и ступень количества. Для раскроя — размеры материала, поля, зазоры, запрет поворота и ограничения оборудования. Для OCR — несколько реальных сканов и контрольные значения.

Готовый репозиторий не заменяет сведения поставщика. В этом поиске не подтверждены рабочие подключения к нынешним ЗЕНОН, ФорДА и Дубль В, получение реальных реквизитов через новые клиенты или единая актуальная база закупочных цен.
