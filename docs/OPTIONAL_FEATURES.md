# Дополнения для сметчика

Версия 1.0.7. Подробная инструкция по текущему интерфейсу: [USER_GUIDE.md](USER_GUIDE.md). После распаковки запустите `SETUP_FEATURES.command` на Mac. Скрипт воспользуется автоматическим подбором Python и создаст отдельное окружение в папке данных программы. Затем снова откройте приложение. На Windows с установленным Python 3.12 x64 используйте `SETUP_FEATURES.bat`.

## Прайсы PDF и OCR

Во вкладке «Обновление цен» выберите PDF, файл или прямую ссылку, страницу и режим «Текст и таблицы». Сопоставьте столбцы. Каждая страница обрабатывается отдельно. Сохраняются исходные байты PDF, контрольная сумма, время получения и номер строки на странице. Повторный просмотр использует тот же документ.

Для сканов выберите OCR. Нужен отдельно установленный Tesseract с языками `rus` и `eng`: [официальная инструкция](https://tesseract-ocr.github.io/tessdoc/Installation.html). На Mac с Homebrew: `brew install tesseract tesseract-lang`. На Windows используйте установщик по ссылке из официальной инструкции, добавьте каталог Tesseract в PATH и выберите Russian language data. Команда `tesseract --list-langs` должна показывать rus и eng. Установка дополнительных пакетов требует интернета. OCR проверен на синтетическом англоязычном скане; русский языковой пакет в среде разработки отсутствует. Ошибки распознавания нужно сверять с оригиналом.

## Zenon и Forda

Адаптер Zenon поддерживает однозначный Product/Offer и ограниченный разбор публичной карточки. При изменении разметки, цене «по запросу», нескольких ценах или отсутствии рублёвого обозначения он завершится с объяснением. Артикул и единица сверяются со справочником.

Forda: поддерживаются Product/Offer и публичный JSON с единственной ценой и явно указанной валютой. Формат ответа сайта может отличаться: первый элемент диапазона и неизвестная валюта не принимаются. В таком случае получите CSV/XLSX/PDF у поставщика. Обход авторизации, CAPTCHA и блокировок не выполняется.

Живое успешное получение цен Zenon/Forda не подтверждено в среде разработки: предыдущие обращения получали HTTP 502. Адаптеры проверены на контролируемых примерах, а не на действующих коммерческих прайсах. Для подключения понадобятся точные URL, регион, артикулы, единицы отпуска, НДС и условия поставки. Код стороннего проекта Vink не копировался.

## Расписание и журнал (1.0.3)

Сохраните источник с публичным URL и сопоставленными столбцами. Во вкладке «Расписание цен» задайте интервал 1–168 часов, поставьте флажок и нажмите «Сохранить». До этого фоновых обращений нет. Проверки работают только при открытом приложении; пропущенные во время сна/закрытия проверки объединяются в одну. Первая плановая проверка — через выбранный интервал, кнопка «Проверить сейчас» доступна сразу.

В журнале сохраняются последние 200 результатов (показываются 100). «Открыть» загружает сохранённый документ без нового обращения к сайту. Укажите дату прайса, если она известна, проверьте сопоставление и подтвердите выбранные цены. Дата старого прайса не переносится на новый документ. Ошибка поставщика не меняет справочник или сметы. Журнал и настройки находятся в `price-monitor.sqlite`; включайте его вместе с базой и исходными документами в резервную копию.

## Отдельное окно и сборка (1.0.4)

На Mac после установки дополнений запустите `START_DESKTOP.command` или `AdvertisingEstimator.app`. Обычный `START_MAC.command` оставлен для браузера. Python подбирается прежним автоматическим установщиком. На Windows: Python 3.12 x64 с Python Launcher, `SETUP_FEATURES.bat`, затем `START_WINDOWS.bat`. Для отдельного окна Windows нужен системный WebView2; при его отсутствии используется браузер. [Документация pywebview](https://pywebview.flowrl.com/api/).

Нативная сборка выполняется на той системе и архитектуре, для которой предназначено приложение. `BUILD_MAC.command` и `BUILD_WINDOWS.bat` создают пакет в `dist-native`. В исходниках есть `.github/workflows/desktop.yml`: после загрузки проекта в ваш GitHub-репозиторий запустите workflow вручную. Подготовлены три среды: Mac Apple Silicon, Mac Intel, Windows x64. [Список сред GitHub Actions](https://github.com/actions/runner-images). Кнопка сборки пока не запускалась в GitHub: внешний репозиторий к рабочей копии не привязан.

`requirements-lock.txt` фиксирует зависимости для Python 3.12 с хешами. Для повторения окружения: `python -m pip install --require-hashes -r requirements-lock.txt`. Обычные установщики дополнений совместимы также с Python 3.12 x64 и используют фиксированные прямые зависимости; на старых версиях Python доступность системных пакетов проверяется при установке. Полная побайтовая идентичность нативных сборок не заявляется: ОС, инструменты подписи и образ GitHub могут изменяться.

В этом архиве `.app` является запускающей оболочкой с исходниками. Готовые автономные `.exe` и подписанный/нотариально заверенный `.app` нужно получить нативной сборкой. Сертификаты Windows/Apple не включены. Проверены ресурсы, расчёт и жизненный цикл окна с тестовым WebView; реальный интерфейс на Mac/Windows требует проверки на устройстве, включая загрузку файлов и сохранение PDF.

## Раскрой и векторные чертежи (1.0.5)

Во вкладке «Раскрой и чертежи» введите размеры листа, отступы, зазор, вылет и список деталей. До 100 типов / 200 экземпляров за расчёт; точность ввода до 0,001 мм. Поворот разрешается для всей раскладки: отключите его для материала с направлением. Полученный вариант проверяется на пересечения и выход за границы. Это эвристический раскрой, а не доказанный минимум листов. Кнопка «Листы в смету» добавляет количество с пустой ценой; «Сохранить схему HTML» выгружает чертежи и координаты.

SVG/DXF читаются локально, без отправки на сервис конвертации. Пример `examples/cutting_demo.svg`: габариты 300 × 200 мм, периметр 1 м, сумма площадей 0,06 м². SVG учитывает преобразования групп и масштаб viewBox с физическими размерами. При неравном масштабе по осям, масках, изображениях, ссылках на символы или текстовых объектах экспортируйте чистые контуры. SVG без физических размеров требует явно заданных мм/единицу. SVG без viewBox использует стандартную единицу CSS px (25,4/96 мм).

DXF использует $INSUNITS; для чертежа без единиц задайте масштаб. Поддержаны LINE, ARC, CIRCLE, ELLIPSE, LWPOLYLINE, POLYLINE, SPLINE в плоскости XY. Блоки нужно предварительно разобрать; DWG и CDR напрямую не поддерживаются. Можно выбрать слой. Текст, размеры и точки пропускаются с указанием в результате. Кривые DXF аппроксимируются с допуском 0,01 мм.

В смету переносится только длина резки. Показанная сумма площадей замкнутых контуров не вычитает отверстия или наложения и не должна применяться как расход листа/лицевого материала. Дубли с одинаковой дискретизацией блокируются; чертёж нужно также проверить на перекрытия, иную сегментацию дублей, заходы инструмента и технологическую ширину реза. Фигурный nesting остаётся отдельным рабочим процессом, например в Deepnest, с проверкой его компонентов и локальности конвертации.

## Word и Excel с формулами (1.0.6)

Во вкладке «Документы» выгружается текущая смета. Word содержит предложение заказчику без закупочных цен и внутренней прибыли; реквизиты берутся из профиля компании. Стандартный шаблон можно скачать, изменить в Word и выбрать перед выгрузкой. Сохраняйте поля `{{ heading }}`, `{{ title }}`, `{{ company }}`, `{{ details }}`, `{{ contacts }}`, `{{ client }}`, `{{ date }}`, `{{ status }}`, `{{ total }}`, `{{ tax }}`, строки таблицы `{{ r[0] }}` — `{{ r[3] }}` и циклы rows/notes. Произвольный код, атрибуты Python, макросы и вложенные циклы не поддерживаются. Если нужен только собственный фирменный стиль, меняйте шрифт, размеры, подписи и поля без изменения выражений.

Excel с формулами предназначен для внутреннего расчёта. На листе «Строки» редактируются количество, цена, закупочная кратность и минимальная оплата; на листе «Параметры» — тираж, проценты, способ ценообразования и налоговый режим. `markup` означает наценку на себестоимость; `margin` — долю прибыли в цене до скидки. Пустая цена не равна нулевой; неизвестный налог не превращается в 0. Для намеренно нулевой стоимости укажите число 0. Расчётные ячейки чёрные, ввод — синий на жёлтом фоне. Изменения файла не возвращаются в базу программы. Выгрузка содержит ровно строки текущего заказа: добавление новых строк в Excel требует расширить формулы; удобнее добавить позиции в программе и выгрузить заново.

Пример `advanced_demo.json`: прямые расходы 3 000 ₽; накладные 300 ₽; резерв 165 ₽; себестоимость 3 465 ₽; после наценки 20% и скидки 3% — 4 033,26 ₽. Режим без начисления НДС задан только для учебного примера. Тарифы и налоговые условия своего заказа определите отдельно. Файлы `Customer_example.docx`, `Customer_template.docx`, `Editable_calculation.xlsx` показывают результат.

## Ключи сервисов

Кнопка «Сохранить в системном хранилище» сохраняет только указанный ключ в Keychain на Mac или Credential Locker на Windows. Для использования поставьте соответствующий флажок на текущий сеанс. Сохранённые значения не передаются обратно в интерфейс. При недоступном системном хранилище программа сообщит об этом; незашифрованного запасного файла нет. Проверка наличия и удаление доступны рядом. Настоящие ключи и доступ к системным хранилищам Mac/Windows в среде разработки отсутствовали; проверялась логика с тестовым хранилищем.

DaData: нужен ваш API-ключ и доступ к поиску компаний по ИНН/ОГРН в выбранном тарифе. Secret key для используемого поиска не нужен. Tavily: ваш API-ключ добавляется для веб-поиска и извлечения страниц; это отдельный онлайн-сервис, для локальных расчётов он не нужен. Сетевые ошибки, лимиты и недоступность источника возможны у любого сервиса. Для официальной выписки сохраняется отдельный путь через ФНС; сведения DaData не выдаются за подписанную выписку ФНС.

## Склад

Сначала создайте материал в «Материалах и расценках» и сохраните заказ. «Приход» добавляет остаток по указанному основанию. «Резерв» закрепляет свободное количество за заказом; «Освободить резерв» возвращает его в свободный остаток. «Списать в заказ» уменьшает одновременно остаток и резерв этого заказа. «Списать свободный остаток» применяется к браку или прочим расходам, не затрагивая резервы.

Единицы не пересчитываются автоматически. При изменении единицы материала сначала согласуйте остатки; склад заблокирует операцию с несовпадающей единицей. Удалить материал с остатком или заказ с резервом нельзя. Повтор того же запроса после потери ответа не проводит операцию второй раз. Редактирование истории и отрицательные остатки не предусмотрены; ошибочный приход корректируется списанием свободного остатка с объяснением, ошибочный резерв — его освобождением. Это количественный склад для сметчика: партии, средняя себестоимость, бухгалтерские проводки и синхронизация InvenTree не реализованы.

## Полная резервная копия

В «Моих заказах» кнопка «Полная резервная копия ZIP» включает `workspace.sqlite`, `stock.sqlite`, `price-monitor.sqlite` и сохранённые оригиналы прайсов/выписок. Предельный объём данных — 50 МБ; при большем размере закройте программу и скопируйте папку данных целиком. Системные API-ключи в копию не входят.

Восстановление выполняйте при закрытом приложении в новую пустую папку. Прежние данные сохраните отдельно; не смешивайте базы и документы разных копий. На Mac: `ESTIMATOR_DATA_DIR="/полный/путь/к/новой/папке" /bin/bash START_DESKTOP.command`. На Windows установите переменную `ESTIMATOR_DATA_DIR` в путь новой папки и запустите `START_WINDOWS.bat`. Старый импорт JSON восстанавливает только базу смет; при существующих складских остатках он блокируется, чтобы не потерять связи резервов.

## Проверка перед рабочим использованием

Проверки расчётов, импорта, расписания, складских транзакций и интерфейса используют учебные данные. Excel проверен пересчётом с изменением цены, пропуском количества и сменой налога; Word отрисован и просмотрен. Сетевые ответы ФНС/DaData и поставщиков в автоматических сценариях синтетические. Не подтверждены живые адаптеры Zenon/Forda, русский OCR, системное хранилище на Mac/Windows и нативный графический запуск на этих платформах.

Для разработчика: `requirements-dev.txt` добавляет openpyxl, pypdf и Hypothesis. `tests/browser-smoke.py` использует Playwright и требует отдельной установки Chromium: `python -m pip install -r requirements-browser.txt`, `python -m playwright install chromium`, `python tests/browser-smoke.py`. В среде разработки загрузка Chromium вернула повреждённый архив / тайм-аут; реальный браузерный тест здесь не выполнен. Проверки jsdom выполняются отдельно через `tests/run-ui.py` при установленном Node.js/jsdom.

## Проверка Windows в 1.0.8

Запускатели Windows требуют Python 3.12 x64 (Python Launcher или python в PATH). После SETUP_FEATURES.bat выполните CHECK_WINDOWS.bat. Для окна нужен Microsoft Edge WebView2 Runtime; при отсутствии программа открывается в обычном браузере. См. [порядок проверки](WINDOWS_CHECK.md).
