# Автоматический поиск и установка Python на Mac

Обновление запуска от **12.09.2026**. Сценарий `START_MAC.command` сначала ищет подходящий установленный Python 3.10 или новее. Если он найден, сценарий использует его без загрузки и установки Python. Если подходящего интерпретатора нет, сценарий подбирает официальный установщик по версии macOS и процессору, загружает его и запускает стандартную установку Python Software Foundation.

## Запуск

1. Полностью распакуйте архив в отдельную папку на Mac.
2. Дважды нажмите `START_MAC.command`. Оставьте окно «Терминала» открытым.
3. При отсутствии подходящего Python дождитесь загрузки и проверки установщика. Для этого нужен интернет.
4. Подтвердите установку в системном окне macOS. Если система требует пароль администратора, вводите его только в этом окне. Сценарии программы пароль не запрашивают, не читают и не сохраняют.
5. После проверки Python подготавливаются библиотеки PDF, затем открывается интерфейс сметчика. Finder-пакет AdvertisingEstimator.app выполняет тот же запуск без окна «Терминала».

Если двойной щелчок не запускает текстовый файл из-за отсутствия права исполнения, откройте «Терминал», введите `bash ` с пробелом, перетащите `START_MAC.command` и нажмите Enter. Если macOS сообщает о вредоносном ПО, сначала проверьте файл и сообщение системы. Сценарий не меняет настройки защиты macOS.

## Выбор версии

Список пакетов зафиксирован 12.09.2026 в `scripts/python-packages.tsv`. Установщик выбирает наиболее новую совместимую версию **из этого списка**. Он не обращается к поиску для определения будущего `latest` и не обновляет уже подходящий установленный Python.

| Система при отсутствии Python | Выбранный пакет | Официальный выпуск |
| --- | --- | --- |
| macOS 10.15 и новее, Intel | Python 3.14.7, universal2 | [Python 3.14.7](https://www.python.org/downloads/release/python-3147/) |
| macOS 11 и новее, Apple Silicon | Python 3.14.7, universal2 | [Python 3.14.7](https://www.python.org/downloads/release/python-3147/) |
| macOS 10.13 или 10.14, Intel | Python 3.13.15, universal2 | [Python 3.13.15](https://www.python.org/downloads/release/python-31315/) |
| Более ранняя или неопределённая macOS, другая архитектура | Автоматическая установка останавливается | Требуется отдельно доступный совместимый Python либо обновление системы |

Официальные пакеты universal2 включают компоненты для Intel (`x86_64`) и Apple Silicon (`arm64`). Mac на Apple Silicon работает с macOS 11 или новее. Обозначение `macos11` в имени пакета само по себе не определяет нижнюю поддерживаемую версию для Intel; сценарий использует требования выбранного официального выпуска.

Адреса установщиков:

- [python-3.14.7-macos11.pkg](https://www.python.org/ftp/python/3.14.7/python-3.14.7-macos11.pkg).
- [python-3.13.15-macos11.pkg](https://www.python.org/ftp/python/3.13.15/python-3.13.15-macos11.pkg).

## Проверка и системная установка

Пакет загружается через HTTPS во временную папку с ограниченным доступом. Сценарий ограничивает размер загрузки и время попыток, проверяет точное совпадение SHA256 с записью комплекта и подпись издателя Python Software Foundation средствами macOS.

После системного подтверждения администратора пакет копируется в отдельную временную папку root. На этой копии повторно проверяются SHA256 и подпись, после чего вызывается стандартный системный `installer`. Это обычная установка PSF в систему, включая каталог `/Library/Frameworks/Python.framework/Versions/` и остальные компоненты официального пакета. Она не является переносимой установкой только внутри папки сметчика.

Временные копии пакета удаляются после завершения или обрабатываемой ошибки. Установленный Python остаётся на Mac и используется при следующих запусках. Если системный установщик завершился ошибкой после начала установки, отдельные его компоненты могли уже появиться: сценарий не выполняет автоматический откат системного установщика.

Python распространяется по [лицензионным условиям PSF](https://docs.python.org/3/license.html). В архив входят сценарии и параметры проверенных пакетов; сами установщики скачиваются с python.org при необходимости.

## HTTPS и сертификаты

Некоторые установки Python используют отдельный файл доверенных сертификатов. Если стандартный файл Python отсутствует, при запуске сметчика допускается использовать доступный системный `/etc/ssl/cert.pem` через переменную `SSL_CERT_FILE` только на время процесса.

Эта подстановка выполняется при наличии читаемого системного файла и только если пользователь не задал собственные `SSL_CERT_FILE` и `SSL_CERT_DIR`. Настройка не записывается в профиль оболочки и не изменяет хранилище сертификатов macOS. Проверка TLS остаётся включённой. Сценарий не устанавливает `certifi` и не запускает `Install Certificates.command` автоматически.

Прямой запуск `python3 server.py` и другие программы Python используют свои настройки окружения. При оставшейся ошибке сертификатов сверяйтесь с разделом `Install Certificates.command` [официальной инструкции Python для macOS](https://docs.python.org/3/using/mac.html) и настройками своего подключения.

## Если установка остановилась

| Сообщение или ситуация | Действие |
| --- | --- |
| Не удалось загрузить Python | Проверьте подключение и доступ к python.org, затем повторите `START_MAC.command`. |
| Подтверждение администратора отменено | Повторите запуск и подтвердите установку, если хотите продолжить. |
| Нет прав администратора | Обратитесь к администратору Mac для стандартной установки Python. |
| Не совпала контрольная сумма или не подтверждена подпись | Не устанавливайте этот файл вручную. Получите целый актуальный комплект программы и проверьте соединение; проверки не отключайте. |
| Нет совместимого пакета для версии macOS или процессора | Используйте отдельно установленный совместимый Python 3.10+ либо обновите macOS. |
| Проверка установленного Python не прошла | Сохраните сообщение об ошибке и проверьте завершение официальной установки Python. |
| Python установлен, а браузер не открылся | Скопируйте локальный адрес из окна запуска в браузер. |

При перечисленных ошибках сценарий не переходит к установке непроверенного пакета. Если Python не подготовлен, сметчик не запускается.

## Библиотеки документов

После поиска Python сценарий вызывает runtime_setup.py. При уже доступных совместимых ReportLab/Pillow используется найденная среда. Иначе создаётся окружение пользователя:
`~/Library/Application Support/AdvertisingEstimator/runtime-python-X.Y/`.

В него из PyPI устанавливаются [ReportLab 4.4.9](https://pypi.org/project/reportlab/4.4.9/) и [Pillow 12.3.0](https://pypi.org/project/pillow/12.3.0/) с зависимостями. Администратор для этой среды не нужен. Нужен доступ к pypi.org и files.pythonhosted.org. Системный Python и глобальные пакеты этим шагом не изменяются. Пакеты остаются для следующих запусков.

Сценарий принимает готовые двоичные пакеты, не собирает Pillow из исходников. Выбранные пакеты PDF рассчитаны на Intel macOS 10.15+ и Apple Silicon macOS 11+. Это отдельное требование, более высокое, чем минимум некоторых установщиков Python. При ошибке подготовки сметчик запускается с доступными функциями; прямой PDF-экспорт требует исправления подготовки. Основной XLSX-экспорт без логотипа и импорт прайса реализованы стандартной библиотекой. Логотип требует Pillow.

При повторной ошибке откройте START_MAC.command, проверьте сообщения подключения и совместимость системы. Ограничение одной попытки установки библиотек — 10 минут; сборка исходников не выполняется. Живой запуск подготовки на Mac здесь не проверялся.

## Отдельная сборка APP и пределы проверки

`BUILD_MAC.command` требует уже установленный Python. При его отсутствии сначала выполните `START_MAC.command`; самостоятельной автоматической установки Python в сценарии сборки нет. Сборка `.app` описана в [macos-build.md](macos-build.md).

Исполнение AppleScript, системная установка Python и запуск программы на реальном Mac в среде подготовки не проверены. Выполненные программные проверки и их пределы перечислены в [VERIFICATION.md](VERIFICATION.md).
